# edittr

A small, fast code editor with built-in git. It's a single native binary written in Rust with [egui](https://github.com/emilk/egui) (no Electron, no webview) and runs on macOS, Linux and Windows.

## Features

- **Editor**: syntax highlighting for most languages, line numbers, tabs, unsaved-change markers
- **Explorer**: file tree colored by git status
- **Search in files** (`Ctrl/Cmd+Shift+F`): searches the whole folder in the background as you type, with match case / whole word / regex toggles; results are grouped by file and clicking one opens the file with the match selected. Respects `.gitignore` and skips binary files and files over 4 MB
- **Go to definition** (`Ctrl/Cmd+click` or `F12`, go back with `Alt+Left` / `Ctrl+-` on macOS): uses a language server when available, otherwise a built-in text search that understands common definition syntax (`fn`, `def`, `class`, `const`, `#define`, …)
- **Go to file** (`Ctrl/Cmd+P`): fuzzy search over files git tracks (or all files outside a repo)
- **Source control**: staged and unstaged changes, per-file diffs, stage/unstage/discard (single file or all), commit / amend, switch branches, fetch / pull (fast-forward only) / push
- **Git graph**: branch lanes, merges, branch and tag badges; click a commit to see its stats and patch

Git runs through your installed `git`, so your config, credential helpers, SSH keys and hooks all apply.

## Language servers

edittr uses the standard Language Server Protocol, like VS Code and Zed. If a server is on your `PATH`, edittr uses it. If not, the first time you go to a definition edittr offers to install it (it always asks first):

| Language | Server | Installed from |
| --- | --- | --- |
| Rust | rust-analyzer | official GitHub release (SHA-256 verified) |
| C / C++ | clangd | official GitHub release (SHA-256 verified) |
| TypeScript / JavaScript | typescript-language-server | npm (needs Node.js) |
| Python | pyright | npm (needs Node.js) |
| Go | gopls | `go install` (needs Go) |

Servers edittr installs go into its own folder (`~/Library/Application Support/edittr/servers` on macOS, `~/.local/share/edittr/servers` on Linux, `%LOCALAPPDATA%\edittr\servers` on Windows; override it with `EDITTR_SERVERS_DIR`). edittr also starts servers it finds on `PATH` for Java (jdtls), Ruby (ruby-lsp), PHP (intelephense), Lua, Zig and C#.

## Install

Download from the [Releases](https://github.com/term-guy/edittr/releases) page:

- **Windows**: `…-setup.exe` (installer: Start menu, optional "Open with edittr" right-click menu and PATH entry; no admin rights needed) or `…-portable.exe` / `…-portable.zip` (no install)
- **macOS**: `…-macos-universal.dmg` (Apple Silicon and Intel). The app isn't notarized yet, so the first time, right-click the app, choose **Open**, then confirm
- **Linux**: `.deb` (Debian/Ubuntu) or `.tar.gz` (any distro; run `./install.sh` to install into `~/.local`), for x86_64 and aarch64

Windows may show a SmartScreen warning because the binaries aren't code-signed yet.

## Releasing

Push a version tag and GitHub Actions builds and publishes everything:

```sh
git tag v0.1.0
git push origin v0.1.0
```

The version comes from the tag. Running the `release` workflow by hand builds all packages as workflow artifacts without publishing a release. The app icon is generated by `packaging/make_icon.py`.

## Build and run

```sh
cargo run --release -- [folder-or-file]
```

On Linux you need the usual windowing dev packages (see `.github/workflows/build.yml`).

## Shortcuts

| Key | Action |
| --- | --- |
| `Ctrl/Cmd+S` | Save |
| `Ctrl/Cmd+P` | Go to file |
| `Ctrl/Cmd+Shift+F` | Search in files |
| `Ctrl/Cmd+click`, `F12` | Go to definition |
| `Alt+Left` (macOS: `Ctrl+-`) | Go back |
| `Ctrl/Cmd+W` | Close tab |
| `Ctrl/Cmd+Enter` | Commit (in the commit box) |
| `Ctrl/Cmd + / -` | Zoom |

Click the active sidebar icon to hide the sidebar.
